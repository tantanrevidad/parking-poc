# Smart Parking — Proof of Concept

A single Streamlit app demonstrating every layer of the Smart Parking system
end to end, running entirely on synthetic (generated) data across **two mock
townships** (Uptown Bonifacio, Eastwood City) with differentiated zone types
(office, mall, residential).

## What's real vs. simulated

| Component | Status |
|---|---|
| Camera feed / occupancy detection | **Simulated** — no real cameras; occupancy is generated from scripted daily curves differentiated by zone type (office, mall, residential) + noise |
| License plate OCR | **Simulated** — plates are fake, "OCR" reads are generated by deliberately corrupting the true plate with confusable-character noise |
| Ticketing system | **Simulated** — fake ticket records, some marked "paid" |
| **Plate-to-ticket matching algorithm** | **Real** — the confidence-weighted, confusable-pair-aware matching logic in `matcher.py` runs for real against the synthetic data |
| **Status state machine** | **Real** — `state_machine.py` implements the actual Free → Occupied-Unpaid → Likely-Vacating-Soon transitions |
| **ML prediction model** | **Real** — a `scikit-learn` `HistGradientBoostingRegressor` is actually trained on the synthetic historical data, with a real time-based train/holdout split, real MAE metrics, and real permutation feature importance |
| **CV feasibility demo** | **Real detection** — YOLOv8n vehicle detection and Tesseract OCR run on real (generic/synthetic) images, matched through the real `matcher.py` pipeline |
| Historical dataset | **Simulated**, but internally consistent — 28 days of 15-minute occupancy readings with realistic daily curves per zone type, weekday/weekend differences, and injected holiday/event spikes across 2 townships |

The goal: every "business logic" component (matching, state transitions,
model training, prediction, CV detection) is genuinely doing the work
described in the project plan. Only the physical-world inputs (camera
frames, real plates, a real ticketing system) are stand-ins.

## Setup

```bash
pip install -r requirements.txt
python generate_data.py     # builds data/parking.db (also runs automatically on first app launch)
streamlit run app.py
```

Then open the URL Streamlit prints (usually http://localhost:8501).

### CV Feasibility Demo (optional)

The CV demo requires additional setup:

1. **Install Tesseract OCR** — download from
   [github.com/tesseract-ocr/tesseract](https://github.com/tesseract-ocr/tesseract)
   (Windows: use the installer from
   [UB-Mannheim/tesseract](https://github.com/UB-Mannheim/tesseract/wiki))
2. Run the demo:
   ```bash
   python cv_demo.py
   ```
3. The demo generates annotated images and matching results in `cv-demo/`.
   The Streamlit app's "How the System Senses Parking" tab displays them automatically.

> **Note:** If Tesseract or YOLOv8 dependencies aren't available, `cv_demo.py`
> falls back to a simulated mode that demonstrates the matching pipeline with
> synthetic detection data.

## App tabs

1. **Live Seat Map** — colored grid of slots (Free / Occupied-Unpaid /
   Payment-Pending-Match / Likely-Vacating-Soon), grouped by township.
   Use the sidebar to advance the simulated clock and watch the mix of
   statuses change. Filter by site using the sidebar dropdown.
2. **Trip Planner** — pick a zone and a future time; see the baseline
   heuristic estimate, the trained model's estimate, and the final
   conservative-adjusted estimate, plus the historical pattern behind it.
3. **ML Model Insights** — real holdout MAE for both the baseline and the
   trained model, feature importance, and an actual-vs-predicted chart
   with a zone selector.
4. **Plate Matching Demo** — pick an occupied slot and watch the matcher
   score every candidate ticket in the pool, including how it handles
   commonly-confused OCR characters (0/O, 1/I, 8/B, 5/S, 2/Z).
5. **How the System Senses Parking** — CV feasibility gallery showing
   real vehicle detection and plate reading results from `cv_demo.py`.

## Zone types

Each zone follows a different daily occupancy curve:

- **Office** 🏢 — fills ~8–9am, dips at lunch, drains after 6pm, quiet on weekends
- **Mall** 🛒 — quiet mornings, builds through afternoon, peaks in evening, busier on weekends
- **Residential** 🏠 — high overnight, dips during work hours, flat across weekdays/weekends

## Regenerating data

The sidebar has a "Regenerate synthetic dataset" button, or run
`python generate_data.py` directly. Re-running reseeds with the same random
seed (42) by default for reproducibility — edit `generate_data.py`'s
`random.seed(...)` calls to get different data.

## Notes for the internship review

This POC is intentionally not the production architecture. There's no
Postgres, no FastAPI backend, no Docker, no real-time WebSocket push —
Streamlit's single-process rerun model is enough to prove the concept. The
`Smart_Parking_POC_Technical_Implementation_Plan.pdf` in this project
describes what the real, full-infrastructure build would look like; this
code is the fastest honest way to show the core ideas (predictive
availability + confidence-weighted matching + graceful status states + CV
feasibility) actually working.
